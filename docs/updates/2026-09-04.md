# Development Update — 4 September 2026

Two pieces of work: a branded homepage entrance animation, and a set of
corrections to the header's own motion.

## Homepage entrance animation

The homepage hero now opens with a branded entrance. It is not a loading
screen: the cream-to-orange gradient and the three statement lines are
permanent parts of the hero, and only the mask hiding them is temporary.

Full specification: `docs/specs/STARTUP-INTRO.md`.

- 0–250 ms solid orange, 250–1,150 ms the mask retreats and the gradient is
  uncovered from the top, 650–1,850 ms three statement lines fall in 100 ms
  apart, 1,850–3,850 ms the navbar enters.
- The lines read "Make it Right / Make it Simple / Make it Work", each closing
  word set in the display italic. They are real text, not decoration, so they
  stay readable by assistive technology.
- Each line is placed independently in the hero rather than stacked, and falls
  from above it — accelerating, then settling — rather than fading in place.
- Timings live once in `app/_lib/intro.ts` and are read by the component, so
  the specification and the code cannot drift.

It was built and reviewed in three gated stages — background, then statement
lines, then navbar — each verified on a real device before the next began.

### Reveal: a mask, after two attempts that were not

The reveal is a soft CSS mask retreating down a stationary gradient. Only the
mask boundary moves; the gradient never scales, translates or fades, so it
arrives in its true proportions.

Two earlier approaches were replaced:

1. **A sliding solid overlay.** It had to be tall enough to cover the bottom of
   the viewport *and* offset enough to keep its feathered edge above the fold,
   and it was failing the first of those — 150svh at −34% left a 1svh
   uncovered sliver.
2. **A transform-driven curtain.** Chosen to avoid repainting a mask every
   frame, but it made the mobile jitter worse rather than better.

The mask removed the whole class of geometry bugs along with the extra element:
there is now nothing that has to sit above the site chrome, and nothing that
could intercept a click.

### Statement lines: motion and styling are separate elements

Each line is an outer wrapper that GSAP animates and an inner paragraph that
carries the type. That split is not tidiness.

GSAP's `_parseTransform` reads an element's computed `rotate`, folds it into
its own `transform` matrix and writes inline `rotate: none` so it cannot apply
twice. A `rotate-*` class on the animated element therefore survives the fall
and then vanishes when that transform is cleared. Worse, CSS composes `rotate`
before `transform`, so the folded matrix rotates the translation too and the
line drifts sideways by `distance × sin(angle)` — about 47px at 3° over a 900px
fall. Both symptoms came from GSAP and the class sharing one element. Keeping
the tilt on a child GSAP never touches fixes both, and the fall is then
strictly vertical.

### How far each line starts above the hero

Measured per line, from the painted extent rather than the layout box.

A single figure — the hero height — was not enough. A line placed at
`bottom-[-5%]` starts below the hero's own bottom edge and stays visible by
exactly that 5%; a tall line near the top needs its own height counted too. And
the layout box excludes the tilt, which is applied after layout and reaches
roughly `width × sin(angle) / 2` past the wrapper's edges, and excludes glyphs
spilling out of a `leading-[0.95]` line box.

The measurement takes the union of the wrapper's client rect and its children's
— a rotated element's client rect is its axis-aligned bounding box — after
neutralising the transform, since the CSS start state would otherwise be
reported as the position.

### Fail-safes hold still; they do not animate

Each of the three CSS fail-safes is a 1 ms snap on a 3,000 ms delay, not a
reproduction of the movement.

An earlier version reproduced the animation in CSS and raced the dynamic GSAP
import: the fallback began travelling, then GSAP arrived and reset everything
to the start — a visible backward jump. Holding the start state still means the
timeline begins from exactly what is on screen, with nothing to reset.

### Strict Mode

Two separate defects, both from React discarding the first effect pass.

**The animation was consumed.** Cleanup marked the intro as played, so the
surviving mount had nothing to do. The async continuation is now guarded with a
`cancelled` flag, and a run counts only when the timeline is actually built.

**The gradient flashed once.** The discarded pass's cleanup cleared the marker
and revealed the gradient; the replacement setup then awaited `import("gsap")`,
which yields — and the browser painted the revealed gradient before GSAP could
hide it again. The visual restore is now deferred by one microtask and gated on
a generation token, so a Strict Mode replay identifies itself and does nothing.
A microtask rather than an animation frame, because microtasks still run in a
background tab and drain before paint.

### Cleanup removes inline styles rather than overwriting them

`restore()` calls `removeProperty("transform")`, not `transform = "none"`.
Overwriting deleted GSAP's folded rotation while its own `rotate: none`
suppression was still in place, so a tilted line ended the sequence flat.
Removing hands every property back to the stylesheet, which is where the
finished state is defined.

### Navbar hidden before the first paint

The header's background was visible above the hero at the start, because the
attribute that hides it was set by React after hydration. A small blocking
script in the root layout now sets it before the first paint. The whole header
is hidden as one element — background, border, shadow, logo and links.

Because a blocking script cannot run on a client-side navigation, it also acts
as the direct-load check. Without scripting it never runs, so the navbar is
simply visible, and a CSS fail-safe brings the header back if the timeline
never takes over.

The script lives in the root layout's `<head>` and `<html>` carries
`suppressHydrationWarning`, since the attribute is absent from the server
markup by design. This is the pattern documented in the installed Next
guide `preventing-flash-before-hydration`; without the suppression React
reports a hydration mismatch and client-renders from the nearest boundary,
discarding the correction.

### Hero runs behind the header

The navbar strip at the top was a layout problem, not an opacity one: the
header reserves space above `<main>`, so the hero began below it and the page
background showed through.

The hero is now pulled up by exactly that space — `-mt-20`, `lg:-mt-30` — and
made `min-h-svh`, so its background reaches the top edge of the viewport. The
two cancel, so the following section still begins at 100svh at every
breakpoint. `<main>` moved from `overflow-hidden` to `overflow-x-clip` so the
upward overflow is not clipped, and the header from `md:static` to
`md:relative` so its z-index applies over the pulled-up hero. Both are
layout-neutral for other routes.

### Gradient defaults to its finished state

The hidden start is applied only under the pre-paint marker, and the CSS
fail-safe is scoped to it too. Previously the default was "hidden", so an
internal navigation to the homepage could paint solid orange for a frame
before an effect corrected it — effects run after the browser can paint.

### Font correction

EB Garamond was loaded without an italic style, so every `<i>` in the display
face was being synthesised by the browser rather than using the real cut. This
affected the footer headline as well, which has used `toge<i>t</i>her` since it
was built. `style: ["normal", "italic"]` is now requested, and Poppins gained
its 100, 300 and 700 weights so the statement's weight classes resolve to real
cuts; the build serves 48 font files where it previously served 32.

### Wordmark aspect ratio

The header wordmark had a hard-coded pixel width, correct only at one height.
It now uses `aspect-[536/50] w-auto` from the SVG's own viewBox, so `h-4 sm:h-5`
scales it without distortion.

## Header motion

Three separate corrections, none of which touch the entrance animation.

### Mobile navbar background follows the scroll position

Below `md`, the navbar is transparent while the page rests at the top — so the
homepage gradient runs unbroken behind it — and `bg-surface-base` once the
reader has scrolled. Tablet and desktop are unchanged.

`atTop` is derived inside the header's existing scroll listener and its
existing `requestAnimationFrame`, not a second one. It uses two thresholds
rather than one: leaving the top takes 24px, returning needs the page back
within 8px. The gap is hysteresis. A single threshold flickers, because a touch
scroll that comes to rest on the line — or the rubber-band bounce at the top of
a mobile page — crosses it repeatedly.

The slide and the colour share **one** transition declaration,
`transition-[transform,translate,background-color]`. Two utilities would not
work: `transition-transform` and `transition-colors` both write
`transition-property`, so whichever the stylesheet emitted last would be the
only one that ran. `translate` is named explicitly because that is the property
Tailwind v4's `translate-y-*` utilities set — a transition on `transform` alone
would have left the hide-on-scroll with nothing to animate.

### Circular toggle icons cross-fade

The hamburger and the cross were conditionally swapped, so the outgoing icon
was removed from the DOM immediately and had no exit. Both now stay mounted in
one 24px box, absolutely positioned over each other: the one belonging to the
current state turns upright, grows to full size and fades in while the other
turns away, shrinks and fades out. Swapping the two class sets reverses the
movement on close without a second rule.

Shared by the tablet top-bar toggle and the floating header. The button's size,
border and centring are untouched. The mobile drawer is not affected — its open
and close controls are two separate buttons in two separate places, not one
icon being replaced.

### Menu list exit

The menu rows snapped shut. The transition, duration and easing existed only
under `group-data-open:`, so removing the attribute removed the transition
along with it and there was nothing left to animate.

The transition now lives in the base state and only the *timing* is scoped:
opening stays 500 ms, swept, staggered per item; closing is 250 ms,
`ease-standard`, and unstaggered, so the list leaves as one movement rather
than unwinding in reverse. The stagger delay goes with the variant, and
`transition-delay` is `0s` by default, so nothing has to undo it.

Both panels also gained `delay-250 data-open:delay-0`. Without it the panel
collapsed to `max-h-0` under `overflow-hidden` and faded from the first frame,
clipping rows that were still animating; the drawer swept up over them. The
panel now waits out the row exit and then goes, while opening stays immediate.
`inert` is driven by the same boolean, so it is set the instant closing begins.

## Dependency

GSAP core **3.15.0** added with npm. No plugins, no ScrollTrigger.

- No dependencies and no peer dependencies.
- Ships its own TypeScript types; no `@types` package needed.
- `npm audit` reports 0 vulnerabilities after installing.
- Imported dynamically, so it is fetched only when the homepage animation runs.
  Confirmed absent from the other routes' HTML.

GSAP is published under its own Standard "no charge" licence rather than an
OSI licence. It permits use on a commercial website like this one, but is worth
a look if this code is ever shipped inside a paid product.

## Verification

Checks that actually ran, on the final state of the code:

- `npm run lint` — clean
- `npx tsc --noEmit` — exit 0
- `npm run build` — Turbopack, all routes prerendered
- `npm run build -- --webpack` — compiled successfully
- Compiled CSS inspected for every new utility, because a Tailwind class that
  matches no theme entry produces no CSS and no error:
  `transition-[transform,translate,background-color]`,
  `transition-[opacity,rotate,scale]`, `duration-250`, `delay-250`,
  `data-open:delay-0`, `group-data-open:duration-500`, `rotate-0`,
  `-rotate-45`, `scale-75`/`scale-100`, `top-[18%]`, `top-[45%]`,
  `bottom-[-5%]`, `rotate-3`, `text-[clamp(...)]`, and all the
  `html[data-intro…]` rules.
- Cascade order confirmed by byte offset in the stylesheet, since class order
  in an attribute decides nothing: base utilities before their
  `group-data-open:` overrides, `md:bg-transparent` after both background
  utilities, and `.motion-reduce:transition-none` last, inside
  `@media (prefers-reduced-motion: reduce)`.
- Prerendered HTML read from `.next/server/app/`: the statement is a wrapper
  plus paragraph per line with the tilt on the inner element; both toggle icons
  are mounted with `aria-hidden="true"`; all three menu panels render `inert`
  while closed.

### Corrections found by verification

Two of the checks above caught real defects rather than confirming work:

- `top-[45%` was missing its closing bracket, so it compiled to nothing and
  that line had no vertical placement at all.
- A literal example class written inside a code comment was scanned by Tailwind
  and compiled into a real rule, `font-size: clamp(min,preferred,max)`. The
  comment was reworded.

### Not verified here

Browser-interactive behaviour was not exercised: no headless browser is
available in this environment. The following still need a human pass, and are
listed in the specification: first load and hard refresh, internal navigation
in both directions, browser back and forward, the three breakpoints,
`prefers-reduced-motion`, keyboard and skip-link access, the mobile menu after
the animation, scrolling and clicking, throttled CPU, and the browser console.

The header work in particular needs a device check that was not possible here:
whether 24px/8px is the right hysteresis for the navbar background, and whether
the drawer's 250 ms row exit plus 500 ms sweep reads as deliberate or slow.
