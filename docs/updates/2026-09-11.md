## Client logo strip scrolls

The two rows now drift continuously: the top row left, the bottom row right.
Logo order, sizing, spacing, ink and edge fades are unchanged.

- **Seamless loop.** Each row is a track holding its eight logos three times,
  moved by exactly one copy (`calc(-100% / 3)` of the track) and then started
  again. The copy it lands on is identical to the one it left, so the restart
  cannot be seen.
- **Spacing moved from `gap` to padding** after each logo (`pr-14 lg:pr-24`,
  the same distances as before). A flex gap exists only between items, so two
  copies would meet with no space between them and every loop would jump by
  one gap. With padding, each copy ends with the same space it has inside.
- **Three copies, not two.** Two copies only reach the far edge throughout the
  loop if one copy is at least as wide as the strip. The top row is about
  1,470px at desktop size, narrower than the strip on the widest screens.
- **Tracks start at the left edge** instead of being centred. A centred track
  moved by a whole copy pulls its far end short of the edge.
- **Both rows move at the same speed.** Each row's duration comes from its
  estimated length (every logo's ratio × optical, plus spacing) at
  `SECONDS_PER_UNIT = 1.2`, about 30px a second on desktop: 48.9s for the top
  row, 66.9s for the bottom.
- **The second row's fixed offset is gone.** On a track that moves by a whole
  copy, a fixed shift leaves an empty band at one end of the loop. Rows moving
  in opposite directions don't stay lined up anyway.
- **Pauses on hover:** `group-hover:[animation-play-state:paused]` on both
  tracks. Tailwind emits it inside `@media (hover: hover)`, confirmed in the compiled CSS, so a tap on a phone does not freeze the strip.
- **Still for reduced motion.** The animation is `motion-safe:` only, so those
  visitors see two static rows.
- **Announced once.** The second and third copies are `aria-hidden`, so
  screen readers hear each of the 16 clients once.
- **No sideways page scroll.** The strip is `overflow-hidden`, and a transform
  takes no layout space.
- **Tokens:** `--animate-marquee-left` and `--animate-marquee-right`, with their
  keyframes, in `app/tokens.css` next to `scribble`. They are generic: the
  distance and duration come from the element as `--marquee-shift` and
  `--marquee-duration`.

## Proof figure counts again after scrolling back up

The count ran once per page load (`once: true`). It now replays after the
reader scrolls back up past the number and returns to it.

- **Two triggers on the number.** `COUNT_START` (its top at 85% down the screen)
  restarts the count from zero each time it arrives from below. `RESET_AT` (its
  top at the bottom of the screen) returns it to zero once it has fully left
  through the bottom, so the next arrival counts again.
- **The reset happens out of sight.** Resetting at `COUNT_START` would drop the
  figure to zero while it was still on screen, in the bottom 15%.
- **Only from below.** Scrolling down past the number and back up to it leaves
  it at "150+", because it never left through the bottom.
- The tween is created paused and driven by the triggers, with `restart()` to
  count and `pause(0)` to reset. The zero is also written directly on reset
  instead of relying on `pause(0)` to fire `onUpdate`. `pause()` takes a
  `suppressEvents` flag, and gsap's installed type definitions don't say what
  it defaults to.
- Unchanged: the server sends "150+", reduced motion and no JavaScript keep the
  final figure, screen readers hear it once, and the number holds its width
  while it counts.
