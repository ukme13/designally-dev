### Why the stack is not `position: sticky`

It was, twice, and sticky gets the stacking right and the departure wrong.

A sticky box is released by its containing block, which for row `i` works out to
`release = listBottom − rowHeight − stop`. Rows therefore release in order of
`rowHeight + stop`, and that sum strictly increases down a stack whatever the
heights are — so the bottom row always runs out of room first and the stack is
eaten from below one band at a time. Trailing space only delays every release
equally. Sticky also cannot stack the last row at all without trailing space,
because its bottom already is the bottom of the list.

The rows are positioned by hand instead: `held = max(0, stop − natural)` per
row, a `depart` shared by all of them, and `lift = max(0, held − depart)`. One
shared number is the thing sticky cannot express. `depart` is measured from the
LAST ROW LANDING, not from the end of the list — keyed to the list's bottom edge
the section visibly ends underneath a stack that is still parked. Because it is
that row's own `held`, it grows one-for-one with scroll as every other row's
does, so `lift` is constant from completion: the group travels at the page's
speed with no rate to tune.

The focus dim moved into the same writer rather than staying a GSAP tween:
`ScrollTrigger` measures with `getBoundingClientRect`, which would include the
stack's own transform and mis-site the trigger on any refresh away from the top
of the page. GSAP, `CustomEase` and `ScrollTrigger` are all out of this
component now; the ease is a cubic ease-out written inline.

### The media rectangle, and the gap it was opening

- `MEDIA` is `aspect-portrait` (`--aspect-portrait: 4 / 5`), matching the
  situations cards. A project token rather than an `aspect-4/5` literal.
- Going portrait exposed a layout bug that 4:3 had hidden. The media spanned two
  grid rows and `self-start`, and a grid item taller than the tracks it covers
  has its extra height DISTRIBUTED across them — so the image was inflating the
  title's row and opening a gap of a hundred-odd pixels above the description.
- Fixed by nesting: the title and description are now one text column, so the
  grid is three columns and one row and the media is out of the text's sizing
  altogether. `self-start` still holds the image's top level with the title's,
  so the stacked strip is unchanged.
- Two knobs, deliberately separate. `PAD.tail` (the title's own bottom padding)
  is the band's bottom edge, so it sets the stacked air, the image reveal AND
  the reading gap together. A margin or padding on the `<p>` sets the reading
  gap ALONE, because that space falls below the band and the next row covers it.

- The eight fills were `black` on the live page and are `currentColor` here, so

  `BrushUnderline` dropped its hard-coded hex.

  selectable, searchable and announced. `aria-hidden` sits on the media box and
  NOT the wrapper, because inside a hidden subtree that copy would reach nobody.
- Inset from the corner rather than hanging off it: the media reaches column 12,
  so a negative offset would put the sticker in the page gutter and risk
  horizontal overflow. The inset also absorbs the tilt, which throws a corner
  about 20px past the upright box.
- Which row carries it is `STICKER_SLUG` in `service-rows.tsx` — a slug, not an
  index, so reordering the five cannot silently move it. Stated in the component
  because it is this section's art direction, not a fact about the service.

### The floating logo over the footer

- The footer is `bg-action-primary`, the same brand orange as the marked
  sections, and carried no `data-header-tone="light"` — so the floating header's
  orange monogram disappeared into it. Every route, not just the homepage.
- The marker is a rectangle starting BELOW the wave, not the `<footer>` itself:
  the top strip is the cream `CtaWaveShape`, and a white logo would have
  vanished into that instead. Erring below the wave is the safe side — an orange
  logo on cream reads, a white one does not.
- The wave is a curve and the marker is a rectangle. That is the deliberate
  limit of ADR-004's approach, not an oversight.

### Known gap: the tone system cannot force orange

Both pixel wipes briefly hide the logo. The cover reaches the top of the screen
before the destination section does, so for the last moment of each transition
the logo is orange-on-orange (entering `#services`) or white-on-white (entering
Proof). ADR-004 only has a marker that ADDS white; expressing "force orange
here" is an amendment to that decision rather than a tweak, so it is not done.
