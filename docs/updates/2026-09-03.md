# Development Update — 3 September 2026

First build session on the 2026 rebuild. The repository moved from the
Create Next App starter to a scaffolded multi-route site with a corrected
token layer and a shared control system.

## Design token corrections

Two defects in `app/tokens.css` were found by inspecting the compiled
stylesheet rather than the source.

- **`--text-body` was declared twice with two different meanings.** The
  `@theme` block set it to `1rem` (a font size) and the `:root` block then set
  it to `#333333` (a colour). Both resolve on `:root`, so the colour won and
  the generated `.text-body` utility evaluated to `font-size: #333`, which is
  invalid and was silently dropped. It only looked correct because the
  inherited size was also 16px.
- **`tracking-label` generated no CSS at all.** It was used 11 times.
  `--text-label--letter-spacing` is a modifier on the `text-label` font size,
  not an entry in the `--tracking-*` namespace, so no utility existed.

Fixes:

- The semantic text-colour family moved off Tailwind's reserved `--text-*`
  namespace to `--ink-*`. Class names are unchanged, because they derive from
  the `--color-text-*` mappings in `@theme inline`.
- Added `--tracking-label: 0.02em`.

Eight of the eleven `tracking-label` uses were redundant — `.text-label`
already carries that letter-spacing. Only the three paired with `text-sm` or
`text-xs` were actually missing it.

No palette or contrast changes were made.

## Route scaffold

Seven routes were added, all Server Components, all prerendered static:

`/works/`, `/services/`, `/about/`, `/insights/`, `/contact/`,
`/privacy-policy/`, `/cookie-policy/`

- `trailingSlash: true` in `next.config.ts`, matching the URL structure in

- Header, footer and a skip link moved into the root layout. The homepage no

  About content.

No CMS, database, form provider, sitemap, robots file or service detail pages

## Navigation

The header was rebuilt to match the original designally.co header:

- Three columns at 1024px and above — wordmark flush left (25%), navigation
  centred (50%), outlined contact pill flush right (25%).
- The wordmark is the original SVG, rendered as a brand-orange fill masked by
  the file. An `<img>` cannot take the colour from CSS.
- In flow, not sticky, transparent, with `0 / 24px / 40px` vertical padding
  across the three breakpoints.
- The mobile toggle is the original's 51px circular orange-outlined button,
  swapping a bars mark for a close mark through the CSS `open` variant.

The original's colours already existed in the token file — its brand orange is
`--action-primary` and its nav ink is `--ink-primary` — so no tokens changed.

The scroll-triggered floating header from the original site was not rebuilt.

`SiteHeader` and `SiteFooter` remain Server Components. Two small client
islands support them: `mobile-menu.tsx`, which closes the panel after a
client-side navigation, and `nav-link.tsx`, which marks the current page.

## Shared controls

Nine pill buttons and four arrow links were duplicated class strings across six
files. The solid orange call to action alone appeared five times as an
identical ten-class string.

- `app/_components/button.tsx` — variants `primary`, `secondary`, `outline`,
  `inverse`. Polymorphic: a path renders `next/link`, any other href renders an
  anchor, no href renders a `<button>`. Server Component.
- `app/_components/text-link.tsx` — the arrow link, tones `default` and
  `inverse`.

Both use a plain variant map rather than a variants library, to avoid adding a
dependency.

Two issues were found and fixed during the migration:

- The shared base class originally included `justify-center`. Tailwind emits
  `.justify-center` after `.justify-between`, so the two full-width call sites
  that passed `justify-between` were silently losing. Class order in the
  attribute does not decide the winner. The base class now sets no `justify-*`
  or width at all.
- `gap-4` overrides were removed for the same reason; the base `gap-3` applies
  everywhere.

The contact pill in the header changed height from 50px to 45px as part of
this. That is a correction — the original measures 45.2px, and the earlier
hand-written version used the wrong line-height token.

## Search foundations

`app/sitemap.ts` and `app/robots.ts` were added, both prerendered static.

- `app/_lib/site.ts` holds the production origin. `metadataBase`, the sitemap
  and robots.txt all derive from it, so the domain is written once.
- `app/_lib/routes.ts` is the registry of public routes, each carrying an
  `indexable` flag, change frequency and priority. The sitemap filters on that
  flag, so a page cannot be listed while also declaring `noindex`.
- Sitemap URLs carry trailing slashes and match each page's declared canonical
  exactly. A sitemap entry that disagrees with a canonical is a conflicting
  signal.
- The two unfinished legal pages are excluded from the sitemap but
  deliberately **not** disallowed in robots.txt. A crawler has to fetch a page
  to see its `noindex`; blocking it would leave the page indexable from
  external links while hiding the directive meant to prevent that.
- `trailingSlash: true` correctly exempts files with extensions.
  `/sitemap.xml` and `/robots.txt` serve directly, and the trailing-slash forms
  redirect back to them.

`lastModified` is currently the build time. That is honest while content
changes every build, but it should become a real per-document date once
content is managed, or routine redeploys will claim every page changed.

Before deploying to a staging or preview domain, block that host at the
platform level. `robots.ts` allows everything and cannot tell which domain it
is serving.

## Service detail pages

Five service pages now exist under `/services/`:

`brand-strategy`, `branding-identity`, `rebranding`, `websites`,
`creative-partner`

- Built as one dynamic route, `app/services/[slug]/page.tsx`, with
  `generateStaticParams()`. All five prerender as static HTML.
- `dynamicParams = false`, so an unknown slug returns 404 rather than being
  generated on request.
- Content lives in `app/_lib/services.ts`, shaped to match the Service document
  in `docs/product/CONTENT-MODEL.md`. Moving to a CMS should mean replacing the
  data source, not rewriting the pages.
- Page sections follow the service page requirements in
  `docs/product/WEBSITE-BRIEF.md`: situations, decisions, what the engagement
  may include, how the work happens, proof, common questions, next step.
- The services index now links to each page instead of listing them as text.
  Each detail page links to the other four, which satisfies the brief's
  requirement that pages link naturally to related services.
- The five paths are derived from the service list in `app/_lib/routes.ts`, so
  adding a service reaches the sitemap without a second edit.

`typicalDuration` and `relatedProjects` exist on the type but are deliberately
unpopulated: no engagement duration is confirmed for publication, and related
projects need permission and evidence review. Both are marked as draft on the
page rather than filled with estimates.
